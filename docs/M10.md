## Boundaries and external effects

The selected operation reuses M9's hybrid C and original-instruction-modeled leaves.
Every executed modeled instruction is checked against the authenticated ELF, and
uncaptured memory/hardware accesses fail. This is functional reconstruction under
PCSX2 defaults, not all-C, byte matching, a native port or whole-game equivalence.
FP flags, exceptional inputs, cycle timing and hardware execution are not modeled.
M9's alternate camera branches still fail closed.

The coordinator's other calls remain external: before the selected pair it calls
`31bb80`, `198f60`, `17f6d0`, `17f2d0`; afterward it calls `13b6e0`, `1430a0`,
`143100`, `12bc70`, `18c520`, `143150`, `1431a0`, `25c170`, `182480`, `13ce80`,
`137890`, `189be0`. Its counter writes and these calls are surveyed instruction
facts, not reconstructed behavior. The reached dispatcher active branch contains
no indirect callback. The representative neutral/held/release/zero dependency
survey also reached no modeled indirect transfers or unmapped hardware accesses;
its 22 modeled leaf entry points and observed external interframe changed pages
are recorded in [dependency-survey.json](../evidence/m10/dependency-survey.json).
The survey is bounded to those four representative stages. Existing active-update/model leaves handle their reached
engine/math/animation/terrain effects by calculation, not capture replay. No
collision, general animation or complete gameplay-frame subsystem is added.

Each M10 frame begins with an independently captured original-game dispatcher-entry
state. The connected reconstruction calculates the relevant player movement,
dispatcher effects and camera response, including the cleared `+428` and every
previous-position lane. The complete resulting 1,344-byte player and 336-byte camera
structures, including unchanged bytes inherited from entry state, match the next
independent original-game checkpoint across all 11 verified handoffs. No external
writes to these structures were observed between the checked frame boundaries.
The independent review sampled writes in four frames: C writes 393–409 of 1,344
player bytes and 261 of 336 camera bytes; remaining bytes retain entry-state values.
These write counts describe those four sampled frames only. This demonstrates the
selected connected operation, not autonomous reconstruction of every inter-frame
engine effect. The earlier control run checked a smaller
field subset; the final continuity run strengthens that boundary without changing
C calculation or the negative controls. Other work between coordinator
iterations (input polling, other actors, timers, rendering) is supplied by the next
entry capture and remains external; its output is not claimed reconstructed.

Full state comparisons retain the established exclusions: guest call-stack scratch
`01fe0000..02000000` differs between host C and guest frames. The separately
identified 256-byte libpad IOP DMA receive buffer may change asynchronously, and
is excluded only if calculation neither reads nor writes it. All 16 KiB of
scratchpad and remaining EE memory are compared. Excluded differences are reported;
unexplained differences are failures.

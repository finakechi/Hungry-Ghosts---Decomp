# M13 — continuous player movement, collision and camera

## Resume here

**M13 extends the M8–M12 reconstruction to continuous, input-driven player movement:**
each frame begins from the preceding reconstructed frame's carried state instead of a
captured original dispatcher-entry state. One authenticated original-game starting
state, the recorded controller input, and the reconstructed per-frame path produce 20+
consecutive frames covering free approach, wall contact, sliding turn in contact,
release, braking to zero and stationary updates, with history and the same-frame camera
on every frame.

The inter-frame gap is closed by newly reconstructed original behavior: the observed
prefix of the per-frame coordinator `0012f850` (the `3fa190` frame-counter increment
with its negative-wrap reset (`bgez` guard), the `0031bb80` edge-counter sync, the `3f9ff8` clear and
the guarded `46e118` increment) and the engine counter advance body `001379f0` of
`00137890` (`46d930`/`46e110` increments with the −1 clamp and the 108000-frame
mega-counter path). The coordinator's remaining engine service calls are declared
external host seams; their memory effects are provably outside every reconstructed
domain in the observed frames.

## Inter-frame write evidence

Diffing consecutive original M12 captures (camera-return of frame N against the next
dispatcher entry, 11 pairs, frames 1209–1220) shows exactly what the original writes
between frames:

| Domain | Observed writes |
|---|---|
| player structure `3f92d0..3f93ff` | **0 bytes in every pair** |
| camera structure `3f9860..3f99af` | **0 bytes in every pair** |
| frame counters `46e110`/`46e118` | +1 each per frame (low byte changes) |
| frame-counter copy `3fa190` | +1 per frame (the coordinator's `bgez`-guarded increment) |
| edge counters (`3fa040/3fa050`, `3f9e34/38/3c +0x210/0x220`) | the 0031bb80 sync |
| input pad area | stick/button bytes only on input-change frames |
| guest stack, kernel low RAM, other actors/render state | thousands of bytes, all engine domains |

The only inter-frame-written data the reconstructed per-frame path reads is the
**stick X/Y input** (`3eaf0c`/`3eaf10`; the read-set instrumentation of a complete
frame recorded every bus load). Scratchpad regions our path reads (`0x500–0x53c`,
`0x700–0x70f`) are rewritten by the original between frames but are overwritten by
the reconstructed camera head matrix (`0012bd00` C) before anything consumes them.

## Implemented safeguards

HGExportSet reserves a new destination exclusively, writes into .partial, and
publishes COMPLETE.json with file hashes only after completion. .incomplete
remains on failure; consumers reject it. A crash after manifest publication but
before marker removal fails closed. Existing destinations always refuse.
HGExport itself was executed successfully in read-only headless Ghidra on the M3
copy. Its Java transaction is also exercised directly with synthetic files.

Builders accept an explicit snapshot directory or exactly one candidate. They
reject ambiguity, missing files, partial sets and manifest hash mismatches.
Legacy explicit exports remain supported; legacy lacks completion guarantees.
Byte assemblers now label byte verification only; historical committed packets
are preserved unchanged. Inventory changes to reviewed entries require explicit
reason/replacements JSON, preserving previous records in review_history.

Bound receipts record relevant source file hashes (including dirty/new files),
source revision, dirty status, Python version, labeled input digests, command
identity and limitations. Relevant source changes invalidate a receipt; docs-only
commits do not. Shared verifier content is checked against the existing PS2DInfo
pin before import. The M2 differential receipt also records PS2DInfo HEAD.
Use hg_check_binding.py with the same complete labeled inputs to check freshness.
Receipts are reproducibility checks, not signatures or proof of honest capture.

The runtime CLI requires the original full image hash and binds raw/post/profile/
emulator/image digests with consistent captured metadata. It labels saved reanalysis
as saved-runtime, never a fresh behavioral run. Existing captures cannot establish
input history merely from INI flags. Fresh-runtime correctness promotion is not
implemented; new M3 observation below is explicitly code presence only.

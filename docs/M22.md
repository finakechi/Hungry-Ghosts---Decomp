# M22 · SG2IOP audio service and sample playback

M22 connects the existing EE bank-registration and play-request code to the
Japanese game's SG2IOP service. It carries an independent IOP command queue,
SPU2 sample RAM, and voice state across RPC calls. The original-instruction
comparison covers the transfer handshake and the ordered SPU2 writes for two
fresh title cursor moves and a confirmation cue. The host model renders a
stereo preview from the authenticated sample bytes.

The implementation checkpoint is
`a4ee75ab4317d6230d9a442fc7fd3f10ae47caf7` on local branch
`research/m22-audio-service` in `decomp-m22`. M21 and M22 share the local
integration base `b855eb93fa797eded31c1849f2bb69d68470609a`. On that branch
`970e7acb1b87c1b8f7397b763d655730780199fa` is the tested code revision,
followed by the integration documentation and receipts. M21 was at

The sample path starts at the existing `HGAudioBus` and the SShd registration
worker. It ends at ordered LIBSD/SPU2 effects and bounded PCM. Acceptance for
this slice requires correct SIF acknowledgements, exact sample bytes at their
SPU2 destinations, separate voice state across requests, and a playable
signal that responds to key-off or sample end. The EE sequence scheduler
still supplies resolved voice parameters and sample offsets through the
adapter described below. Streaming and full SPU2 emulation are outside the
selected slice.

### Transport and state

| Stage | Original locations and behavior |
| --- | --- |
| EE enqueue and send | `002acf60` writes four little-endian words to `00a801c0 + 16*i`, advancing the cursor at `00a80180` modulo 512. `002ad288` binds RPC `11223344`. `002ad138` calls RPC function 0 with size `count*16` and a `1c0`-byte reply at `00a821c0`. |
| IOP receive and dispatch | SG2IOP `3d58` registers the service and callback `3de0`. The callback passes four words per record to `408c`; the ring begins at module offset `4ba0`, with indices `6ba0` and `6ba4`. `3c4c` drains FIFO through the handler table at `4ad0`. The callback returns the reply at `6fb8`. |
| EE staging and cleanup | `00157060` stages resource bytes at the location from `resource+18`, using `0010af40` to allocate IOP heap memory and `00156f20` for SIF DMA. `002a7560` posts upload ID `13` through the EE transaction queue at `00a823c0`. `002a7590` polls the status word; `002b5428` records the SPU2 byte address in the live EE slot at `+0c`. `0010b0a8` wraps heap RPC function 2 at `0010b030` to free the IOP allocation. The older harness labeled this call MSCOM. |
| IOP transfer and ACK | SG2IOP `1690` enqueues worker kind 1 at `6ba8` and sets phase 1 at `6fb0`. Worker `474` calls LIBSD ordinal 17 `VoiceTrans(0, 0, source, destination, size)` at `534` and waits through ordinal 19 at `54c` before storing phase 2. `3ee4` publishes busy at reply `+184`; phase 2 returns 0 and resets the latch. |
| Voice state reply | `3f94..4060` reads ENVX on two cores with 24 voices each, core-major, through LIBSD ordinal 6. Fresh PCSX2 snapshots have identical 48-word arrays at IOP `56230+6fb8` and EE `00a821c0`. |
| Voice selection upstream | `002ad478` posts a play request. `002b5008` checks the unadvanced variant count and applies the variant index once. The prior C applied it twice. With the repair, the registered boot bank resolves `00b55763` for both captured cursor requests. The `ff 41 f7` bytes from `002ad748` enter the EE sequence channel at `00a6c530`; the SG2IOP transport uses the separate four-word queue. |

The SG2IOP receive logic in the original uses `size >> 4` and an unchecked
table dispatch. The host API validates whole records and rejects a malformed
batch before writing hardware or changing queue state. It limits a batch
to 511 records and supports one in-flight upload. If the EE ring is full
when an upload is pending, the adapter sends the existing records first
and submits the upload on the following flush. The host uses an explicit
worker step before the next status poll. That is a bounded scheduling
policy for the separate original RPC and DMA threads.

### Supported commands

Arguments below are words 1–3. Physical voice indices 0–23 use core 0 and
24–47 use core 1.

| ID | SG2IOP handler | Input and original dispatch |
| --- | ---: | --- |
| `00` | `06e0` | No-op |
| `01` | `06fc` | Voice, left gain, right gain. The handler remaps signed negative arguments before the two LIBSD parameter writes. |
| `02` | `08e8` | Voice, ADSR1, ADSR2. Uses the low halfwords. |
| `03` | `0a44` | Voice, SPU2 start byte address, unused. LIBSD ordinal 9 writes the high and low SSA halfwords in word-address units. |
| `04` | `0b04` | Voice, packed root/note/signed fine offset/bend, and packed bend scale and rate scale. The reconstructed arithmetic generates the pitch curve with measured residuals. This slice requires a table index in 0–607, a note delta in ±36 and a rate scale in 0–`3fff`. |
| `07 / 08` | `1068 / 10bc` | Unused, core 0 mask, core 1 mask. Key-on/key-off register writes. Consecutive writes preserve low-half, high-half and core order. |
| `09` | `1110` | Unused, core 0 mask, core 1 mask. Left and right wet-mix masks. |
| `0a` | `1194` | Unused, core 0 mask, core 1 mask. Noise enable masks. |
| `13` | `1690` | IOP source, SPU2 byte destination, byte count. In this slice the three fields must be 16-byte aligned. |

Retail EE entry points include `002b1668` for ADSR and `002b1188` for SSA.
The voice preparation loop posts gain at `002b2930` and pitch at
`002b2c90`. It emits the switch masks from `002b2cb8..002b2dac`. In LIBSD,
parameter, switch, and SSA writes use `3660`, `371c`, and `378c`.
The verifier executes these original instructions with observed DMA requests
and independently supplied MMIO read values, comparing the reconstructed
writes by address, value, and order.

### Cursor note records

The selected cue begins at member offset `763`. Its first three high-nibble
A events are notes `54`, `53`, and `52`, each with velocity `64` and
instrument 1. `002ae2c0` copies the three payload bytes into the EE channel
queue. Channel consumer `002a96b8` dispatches the A entry through table
`003bd078` to `002ab508`. The handler resolves the instrument with
`002b50e0` at `002ab59c`. The instrument table is at member offset
`2410`, and entry 1 begins at `2834`. The entry gives lower and upper
notes at `+6` and `+7`. The selected 16-byte tone row starts at
`entry+8+16*(note-low)`.

At `002aba38` the handler reads the halfword at tone `+4`. At
`002aba4c..002aba50` it shifts by the channel's bank state and adds
the bank base, then calls the original SSA producer. For this resource
the state is 3, so `1e68 << 3` gives sample offset `f340` and adding
`5010` gives `14350`. Tone `+2/+3` gives the root and signed fine offset.
With the observed default channel envelope, the halfwords at tone
`+6/+8` are the two ADSR arguments. An independent parse of the retail
member matched address, ADSR and packed note fields for all five
cursor voice launches. This maps the data needed by the adapter. The
channel scheduler and physical voice allocator still belong upstream.

The verifier compares all 48 native ENVX reply words at the EE and IOP
checkpoints. Its instruction runs use fixture values at the hardware read
seam and preserve the read order.

A separate saved-SPU2 comparison carried the final register writes across
all three packet sequences. It matched 84 fields across 14 voice observations
(cursor down voices 6–7, cursor up 6–10, and confirmation 11–17). The six
fields per voice were left and right gain, pitch, ADSR1, ADSR2, and SSA.
For this PCSX2 build, core 0 voice records in `SPU2.bin` begin at `2101f0`
with stride `108`. The first five field offsets are `0 / c / 50 / 18 / 1a`,
and the 32-bit word-address SSA is at `58`. On confirmation, voices 16
and 17 had ADSR release phase 4 at offset `4c` and physical ENVX 19224 at
offset `48`. Their earlier EE/IOP reply value was 19400. The release
trajectory remains outside the host model. [PCSX2 voice state definitions](https://github.com/PCSX2/pcsx2/blob/v2.8.2/pcsx2/SPU2/defs.h)

Playback uses carried pitch phase, ADPCM history, signed stereo gain,
loop and end flags, and independent voice stop.
The preview contains 16,000 stereo frames at 48 kHz with 15,769 nonzero
frames. The preview places 800 host frames at the chosen packet boundaries
and then renders a tail. The save states establish packet order and the
selected checkpoints. They give no cycle-by-cycle DMA latencies or
sample-aligned capture of the original mix.

Synthetic checks cover separate cores, independently carried stop and loop
state, natural end, replacement of an uploaded span, clearing the EE slot,
queue wrap, and polling before DMA completion. Wrong key ID, wrong core and
reversed edges each fail their original-instruction comparison. Malformed
IDs/channels, unsupported pitch indexes, misaligned or out-of-range spans
and oversized batches are rejected before dispatch.

## M21 interface

Build `src/audio/audio_engine.c` and `src/audio/audio_iop.c` together with
`-lm`. Include [audio_iop.h](../src/audio/audio_iop.h). The owner of the
guest bus keeps one `HGAudioEeService` and `HGAudioIop` per audio context,
and serializes registration, staging, RPC, DMA stepping and rendering.

1. Initialize the EE bridge and IOP instance. Supply the IOP read callback,
   and optionally attach SPU2 register write, ENVX read and DMA observers.
   The caller owns the EE and IOP guest memory, including the `003e0720`
   table of initial SPU2 bank destinations and the SIF allocation lifetime.
2. Drive `hg_audio_register_entry` with the published SShd resource.
   Route bus targets `002a7560`, `002a7590` and `002b5428` through
   `hg_audio_ee_bank_call`. Supply the existing allocator and SIF DMA paths.
   Route `0010b0a8` to the IOP heap release path. Flush staged packets,
   step DMA, and flush again to deliver completion. Keep ticking the EE
   worker until it returns its resource endpoint.
3. Use `hg_audio_play` to create an EE request. For each resolved note,
   `hg_audio_ee_stage_play_voice` follows that request's bank slot and
   validates the supplied ADPCM byte offset against the uploaded bank.
   Set the caller's resolved physical voice, ADSR, gain and pitch, then
   stage a key-on. Use `hg_audio_ee_post` to stage wire records directly
   when the caller already has them, including multi-voice masks.
4. Flush, then advance the modeled SPU2 with `hg_audio_iop_render`.
   Stage a key-off and flush it before rendering the subsequent samples.
   An explicit key-off makes the selected voice silent in the model.
   EE request retirement and the mapping from each timed sequence to its
   owned physical voices belong to the EE sequence caller.

The host model uses nearest-sample output and immediate key-off. It exposes
original ADSR, wet-mix and noise register requests. ADSR envelope evolution,
noise synthesis, effects, master gain, interpolation, hardware voice
stealing and cycle-accurate SIF/SPU2 timing remain open. The optional ENVX
callback is authoritative for an external hardware backend. Its absence
yields a simple activity envelope. Retail PCM equivalence remains untested.

## Original-byte findings

**Main loop (0011d830).** Initialization (resource init 001431f0, initial
mode `001432c0(00121810)`, two 0011dfd0 waits, EE timer setup), then per
frame: `0095e308 = 0`, 00148970, 0013d970, 00156740, the mode dispatcher
00143240, 00139240, 001467b0, 0013da80, the DMA/VIF/GIF idle wait 00100b80
(nonzero only on timeout), a wait loop on `0095e308`, 00149890, 001496e0
(GS field/bank), `0x10000000 = 0`, `[gp+2f84] += 1`.

**Vblank handlers.** 0011df10 (INTC 2) increments `0095e308` (the main-loop
wait flag) and `0095e300`, and wakes the loader thread `[003f8e34]` when
`003f8e30 == 1`. 0011df80 (INTC 3) wakes `[003f6db4]` when `003f6db0 == 1`.

**Mode block** `gp+2dc0 = 003ead30` (scratch word `700000c0` points to it):
`+0` state, `+1` area index, `+4` handler, `+8` major, `+9` minor, `+a`
sub, `+b` step, `+c/+d/+e/+11/+12` bytes, `+1a/+1c/+1e` u16 timers.
00143240 promotes state 1/4 to 2 and calls the handler for state 1, 2 or 4;
001432c0 and 00143300 install a handler and clear `+8..+27`.

**Modes.**

| Handler | Role |
|---|---|
| `00121810` | boot: first request `00130150(0,0)`, fade, `002cdef0`, two 300-frame logo sequences (`001219e0`), then `00121be0` |
| `00121be0` | lifecycle/title: tick `gp+2f80`; major 0 loads title data and, for a new game, clears `003fa180..+73fc0` and sets the triple `(0,9,0)`; major 1 is the title menu (overlay `00a87880`); 2 installs gameplay `0012d1c0`; 3 continue/data load (`00130150(1,0x69)`); 4 options; 5 area select |
| `0012d1c0` | gameplay: `700000c4 = 2`, accumulator `gp+2f7c += 1.0` (reset above 100000.0), tick `gp+2f80`, majors 0..5 |
| `0012d9a0` | major 5 minors: 0 entry 0012dc90, 1 active play 0012e700, 2 0012f270, 3 003372a0, 4 teardown 0012f800, 5 area load 0012dd60, 6 reload 0012e020 |

Area load 0012dd60 requests the AREA directory `00130150(1, [gp-7dd0][area])`
and the PACK `00130150(2|3, 0012dbd0(1|0))`, where
`0012dbd0(r) = base[b0] + stride[b0]·b1 + (r ? 0x93 : b2 + 0x94)`.
Active play 0012e700 sub 1 calls the coordinator 0012f850 (0012f950 when
`003f9f3e`) and then the event flags 0012fa00; Start (`pad & 0x800`) gives
flag 1, which enters the pause sub state 2 and calls the fade-out
`00139040(8,0,1)`. Pause choice 3 selects minor 4 (teardown 0012f800:
`700000f8 = 1`, mode 00121be0).

**Fade state** `gp+2f40`: 00139040 (fade out) writes 3 and 001390b0 (fade in)
writes 1; 00139010 and 00138fd0 write 2 and 0 immediately. Consumers wait
for 2 after a fade out and for 0 after a fade in; the completion writer is
the per-frame fade service (not a direct `gp`-relative store; not
reconstructed).

## Delivered C

`src/game_lifecycle.c` (1,074 lines) and `src/game_lifecycle.h`: 24 C entry
points for 23 original functions (main is split into `hg_main_init` and one
loop iteration `hg_main_frame`): 00143300, 001432c0, 00143240, 0012d1c0,
0012d680, 0012d7d0, 0012d850, 0012d9a0, 0012dbd0, 0012dc90, 0012dd60,
0012e020, 0012e6d0, 0012e700, 0012fa00, 0012f7d0, 0012f800, 0011d830, 0011df10,
0011df80, 00121810, 001219e0, 00121be0. Every callee outside the file is a bus
call with its original entry address. New host seams: `HG_WAIT_INTERRUPT`
(the vblank wait loop delivers pending handlers) and `HG_CALL_FP_REGS`
(f12–f14 of the next call).

`hg_game_frame_connected` runs one frame of the obs3 corridor from
coordinator entry to the next coordinator entry through the real lifecycle
chain: active-play tail (event flags), main-loop tail (00100b80, vblank wait
with the C handlers, 00149890, 001496e0, `[gp+2f84]`), main-loop head and
the C dispatcher → gameplay mode (tick, accumulator) → major 5 → active
play, suspending at the next 0012f850 call. In this path the M16 stand-in
tick of `gp+2f80` is replaced by the original 0012d1c0 tick; the unchanged
M16 entry `hg_player_frame_continuous` keeps the stand-in.

Both columns use the same interpreted-word record (the M17 lifecycle corridor

instruction-backed row does not change; candidates that became C leave the
external/unknown rows. One C entry (`00a8a070`, AREA1) is outside the ELF
inventory.

C classes require C source with an original-address annotation; byte counts
are whole inventory candidate bodies. `c-fail-closed` means some path of the
C body reaches a domain fault (for the three new ones: FP edge cases of the
accumulator and volume conversions never observed); it is not partial
coverage of the differential, which executes 100% of reachable words.
Instruction-backed words are original instructions executed by the host
interpreter on the connected corridor path (AREA1 body and ELF leaves); they
are never counted as C. Candidates are automatic Ghidra discoveries, not a
verified function total.

**Remaining work, without overclaiming.** About 2.0% of the ELF candidate
instruction bytes have C source (49,020 of 2,469,083), up from 1.5%. Not in
the inventory at all: 13 AREA overlay files (1,722,752 bytes across AREA0–2,
code extent not yet inventoried; only part of AREA1/A1_B00.BIN is examined),
7 IOP modules (217,823 bytes, mostly Sony libraries; `SG2IOP.IRX` and
`SDRDRV.IRX` are the likely game-specific ones) plus `IOPRP271.IMG`, VU
microcode and any script data. No byte-match, full-game equivalence,
recompilation or port is claimed.

## Limitations

- Deliverables A and C are synthetic. The loader, fade service, title and
  pause menus (`00a87880`, `00162750`, …), audio and the coordinator are
  external host models in the sequence runner.
- Native lifecycle evidence is partial: selected regions, sequential reads,
  one non-frame-adjacent pair.
- AREA `0x51` (area 1 AREA directory) is read from the ELF table; no native
  request record of it was captured.
- Area-to-area transitions (sub 5 warp, `0046d92c`) are differential-only;
  no native capture exists.

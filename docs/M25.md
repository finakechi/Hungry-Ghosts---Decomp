# M25 — world initialization and state continuity

M25 extends the M23 world harness into one connected operation:

cold boot → resource publication → actor/bone and player activation →
camera/collision readiness → sustained controller updates → teardown →
clean re-entry.

It also characterizes, separately, the retail initialization steps that were
missing after M23.

**Capability boundary.** The connected session runs two **original synthetic
scenes**. They exercise existing project C on the shared 32 MiB EE RAM +
16 KiB scratchpad guest bus, plus independently written models where no C
exists. Passing them is **not** evidence of retail continuity.

On the retail side, the last observation from a single run is still the first
AREA1 coordinator entry (`0012f850`, M21 `area1-active`). The return from
`00158a10` is supported only by equivalence across separate runs. The earliest
retail dependency with neither C nor an observation is `001e3440`, the state-0
floor snap.

## What was built

### Session API (`src/scene/world_init.{h,c}`, additive)

The M23 path does not change: the M23 synthetic receipt reproduces byte for
byte. The shared APIs are preserved, including `hg_world_harness_guest_ram()`.
A session is opted into with `hg_world_session_create` and
`hg_world_session_select_scene`. Each later lifecycle step then runs the M25
model:

- **Scenes.** `HGWorldSceneSpec` describes a scene: spawn, walls, floor tiers,
  root actors, props, PACK directories, arenas and entry flags. Use
  `hg_world_scene_validate` and `hg_world_scene_builtin`.
- **Readiness.** `hg_world_session_readiness` steps through these states:
  `BOOTED → PUBLISHED → WORLD_SETUP → FIRST_TICK → FADING → ACTIVE → TORN_DOWN`.
  Any failure moves to `FAILED`.
- **Ledgers.** Three ledgers can be read back through accessors: the state
  history, ownership (actor/node alloc and release, handle publish and revoke)
  and effect records (`HG_EFFECT_*`).
- **Snapshot.** `hg_world_session_snapshot` reports readiness, update and tick
  counters, pool free counts, list sizes and `003f9f6e`.
- **New errors.** `INVALID_CONFIG`, `CAPACITY`, `UNSUPPORTED_ENTRY` and
  `LIFECYCLE_STATE`.
- **Provenance.** Three classes were added: `ORIGINAL_BYTES`,
  `RUNTIME_OBSERVATION` and `INFERENCE`.

### Model policies

The model follows rules taken from the original bytes where those are
characterized, and states every remaining assumption:

- **Coordinator `0012f850`.** It runs 18 services in ELF order. The order
  includes `00189be0`, which the existing C `coordinator_frame` leaves out.
  `0046e118` advances only while `gp+2f78 == 0`. After an initialization error
  the coordinator refuses to run.
- **State 0 (`003db540[0] = 001585c0`).** The sequence is:
  1. C `00158a10`.
  2. Floor snap `001e3440(PLAYER, +8.0, −3.0)`. The model treats these
     arguments as a probe span, which is an inference.
  3. The ordinary-entry selector. Event entries fail closed with
     `UNSUPPORTED_ENTRY`.
  4. `+18 = 1`, written in the delay slot of `jal 00158470`.
  5. The tail at `00158968`: rot.x through `001204e0`; `003f9f6e` from the
     sign-extended `lb +4ac` plus `lh +45a`, plus 1 when `+464 == 0`; and a
     128-bit copy of `+30` into `+390`.
- **Rotation helpers.** The helpers right-multiply (`dst = src·R`) in sessions.
  This was measured by running the original `00143c60`, `00143d30`,
  `00143b90` and `00144340`.
- **Node pool.** Pops and binds go through C (`00141de0`, `00141e40`). The model
  supplies the release (push) operation. It refuses double frees and any push
  outside the stack.
- **Actors.** The model provides retire: unlink through `+20/+24`, then return
  the actor to its pool's free list. Allocation uses C `001429b0`.
- **Teardown.** The order is:
  1. C `hg_gameplay_teardown`.
  2. Nodes are retired newest first, then actors.
  3. C dynamic clear for handles `0x96..0x28e`.
  4. The model revokes `0x3f`.
  5. The player and camera are cleared and the fade is reset.
- **Partial-initialization cleanup.** After `CAPACITY`, binding or entry
  failures, every allocation in the ledger is retired.

### Independent checking (`tests/world_session_driver.c`, `tools/verify_world_session.py`)

The checkers hold their own layout constants, plus the ELF coordinator order
and the setup order. They replay the run and do not trust the model. The C
checker and a separate Python re-derivation check:

- **State history.** Only legal transitions occur. A positive run has exactly
  6 events.
- **Ordering.** The 12 sub-0 setup effects occur in order. Every tick follows
  the 18-service order. Setup order is also checked after a failure.
- **Camera geometry.** The eye equals position plus the head offset. The boom
  is 20 long and follows yaw and pitch. Heading is within 2e-2. Pitch equals
  the bias 0.05235988 ± 1e-4.
- **Continuity.** Counters advance once per update. Per-frame displacement is
  at most 1.0, and |dy| is at most 1.8. Every position stays inside the walls
  and on the expected floor.
- **Ownership.** The audit checks the free stack, owner tables, list links and
  tails, the pool free lists and a ledger replay. After teardown it expects
  2048 free nodes and actor pools of 286/40/256.

Each scene's script has 134 post-readiness updates:

| Phase | Updates |
| --- | --- |
| Neutral | 12 |
| Walk with floor response | 26 |
| Turn | 20 |
| Wall contact and slide | 34 |
| Release | 16 |
| Return turn | 14 |
| Release | 12 |

The cycles interleave as A1, B1, A2, B2. Parity compares counters relative to
each cycle and per-operation ledger counts.

### Conflicts and errata recorded against M23

- **`003f9f6e`.** The M23 model writes 0 at state 0. The original bytes and the
  oracle give 1 when `+464 == 0`. In `obs3-000` the value is 0 with
  `+464 = 1`, which is consistent.
- **Camera pitch.** The M23 helpers left-multiply, so the pitch was lost at
  yaw π/2. M25 sessions use the measured right-multiply. The M23 receipt was
  left unchanged on purpose.
- **Capture path.** M23.md cites `local/m21/live/…`. The captures are actually
  under `local/m21/native/full/`.

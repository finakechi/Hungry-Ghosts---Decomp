# M26 · Audio timing and voice management

M26 extends the independently authored M24 HSQ1 sequence processor
(`src/audio/audio_sequencer.{c,h}`) into a timing-aware audio lifecycle on top
of the existing M22 transport (`src/audio/{audio_engine,audio_iop}.{c,h}`):

> **Bank registration → play request → scheduled event consumption → voice
> allocation and contention → ordered service operations → release or
> cancellation → retirement → clean repeat.**

Alongside the independent model, M26 performs bounded read-only reference
research against the authenticated Japanese `SCPS-15046` ELF and the 12 pinned
M22 PCSX2 saved checkpoints to characterize wake timing, channel consumption,
voice attribution, and two-stage retirement.

All legacy M22/M24 APIs and receipts remain unchanged. The timing-aware model
is additive and opt-in (`HG_SEQ_TIMING_CHRONO`). No retail equivalence, retail
sequencer/allocator reconstruction, streaming dialogue (`001564a0`/`00156550`),
full IOP emulation, or retail SPU2/PCM equivalence is claimed.

### 1. Confirmed from authenticated ELF instruction bytes (23 anchors)

- **Wake source (resolved from M24 unknown).** Boot sequence
  `0011d880..0011d8b8` registers `0011df10` on INTC 2 (VBlank-Start) and
  `0011df80` on INTC 3 (VBlank-End) through `00103c40` (`AddIntcHandler`),
  enables both via `00104aa8`, and calls `00156870`.
  - `00156870` calls `002a74b8(0x3c)` (`00a6c3c4 = 60`) and
    `00143360(0x64, 0, 001566c0)`, which binds the audio thread (ID 3 in the
    saved runtime) into `003f6db0 = 1`, `003f6db2 = 0x64`, `003f6db4 = tid`.
  - On each VBlank-End interrupt, `0011df80` checks `lhu 003f6db0 == 1` and
    calls `00104e10(lw 003f6db4)` → `00103ea0` (`iWakeupThread`, syscall `-52`).
  - Thread `001566c0` calls `SleepThread` (`00103e80`, syscall `50`), checks
    `002ad118` (`sceSifCheckStatRpc` idle), and runs the 16-slot scheduler
    `002a7450`.
- **Slot 1 timing (`002add90`).** Advances soft-double `+0x28` by `+0x20` via
  `00115fd8` and loops while `+0x28 >= +0x30` via `00116580`. Retires state-2
  commands to state 0 only when `002a9d18(channel) == 0`.
- **Slot 2 channel retirement (`002a96b8`).** Clears channel `+0x00 = -1` only
  when closing flag `+0x10 != 0` and `002b0cd8(channel) == 0` (no active voices
  owned by that channel).
- **Slot 3 voice retirement and SG2IOP mask order (`002b2438`).** Increments
  voice age `+0x20` each wake and retires a voice when `age >= 3` and
  `002ad0e8(v)` (`ENVX` reply) `< 2`. Enqueues pending masks through `002acf60`
  in exact opcode order: `0x09` (wet), `0x0a` (noise), `0x07` (key-on
  `00a83270..74`), `0x08` (key-off `00a83278..7c`).
- **Release helper (`002b2030`).** Sets release ADSR via `002b1668(v, 0, 8)`,
  sets voice key-off bit in `00a83278..7c`, and writes `+0x1c = -1`.

### 3. Inferences and instrumentation limits (explicitly bounded)

- **Inferred (not directly traced per-frame):** One audio scheduler wake runs
  per NTSC VBlank-End when the SG2IOP RPC is idle, and the rotating cursor
  `00a832a0` advances monotonically across newly claimed voices in class 2.
- **Instrumentation limits / unknowns:**

  - Pending masks at `00a83270..00a8327c` are always `0` at saved boundaries

## B. Independent timing and voice management contract

Added cleanly to `src/audio/audio_sequencer.{h,c}` without altering
`HGSeqConfig`, `HGSeqDecision`, or any legacy M24 behavior when
`timing_mode == HG_SEQ_TIMING_LEGACY` (`0`).

### 1. Five distinct time domains (`HGSeqClock` & `HGSeqDecisionTiming`)

| Domain | Field(s) | Meaning |
| --- | --- | --- |
| Elapsed logical time | `clock.elapsed_ticks` (`uint64_t`) | Monotonic logical ticks accumulated across updates. |
| Request arrival time | `request.arrival_tick`, `decision_timing.request_tick` | Caller-tagged arrival time (`hg_seq_tag_request`) or current clock at adoption. |
| Logical event due time | `decision_timing.due_tick` | Exact logical tick at which an event, note expiry, release expiry, or cancel became due — invariant across schedules. |
| Service / flush time | `decision_timing.service_tick`, `clock.last_service_tick`, `clock.last_flush_tick` | Update boundary when the event was processed and when `hg_audio_ee_flush` was recorded (`hg_seq_record_flush`). |
| Render position | `clock.rendered_frames` (`uint64_t`) | Cumulative PCM frames rendered via `hg_audio_iop_render` (`hg_seq_record_render`). |

The existing 1-tick / 800-frame (60 Hz / 48 kHz) harness cadence is a synthetic
model convention, not measured retail timing.

### 2. Additive public API (`src/audio/audio_sequencer.h`)

- `hg_seq_init_timed(seq, service, config, timing)` — initialize in
  `HG_SEQ_TIMING_CHRONO` (or `HG_SEQ_TIMING_LEGACY`) with explicit policies.
- `hg_seq_configure_timing(seq, timing)` — configure timing/voice policies on
  an initialized sequencer.
- `hg_seq_update_u64(seq, ticks)` — 64-bit tick advance with overflow guard
  (`UINT64_MAX` saturation protection) and 0-tick immediate servicing.
- `hg_seq_tag_request(seq, cmd_index, arrival_tick)` — tag inter-service play
  request arrival time inside a batched update window.
- `hg_seq_tag_cancel(seq, cmd_index, cancel_tick)` — tag mid-batch cancellation
  time so events after `cancel_tick` do not fire.
- `hg_seq_record_flush(seq)` / `hg_seq_record_render(seq, frames)` — track
  service flush and PCM render clocks cleanly.
- `hg_seq_releasing_voices(seq, mask[2])` — query voices currently held in
  deferred release.
- `hg_seq_clock(seq)` — snapshot all 5 time domains and counters.

### 3. Deterministic chronological tick order (`HG_SEQ_TIMING_CHRONO`)

When `hg_seq_update_u64(seq, ticks)` advances from `window_start` to
`window_end = window_start + ticks`:

1. **Zero-time servicing (`ticks == 0`):** Services due retirements, retries,
   cancels, adoptions, and zero-wait events at `window_start` without advancing
   `elapsed_ticks`.
2. **Chronological discrete tick stepping (`t = window_start .. window_end`):**
   At each logical tick `t` (plus immediate arrival/cancel checkpoints):
   1. **Deferred release retirement:** Retire any releasing voice whose
      `release_until <= t` (`HG_SEQ_D_VOICE_RETIRE`), making it reusable only
      after the hold expires.
   2. **Pending/active cancel and bank/command loss:** Consume `ff 41 f7`
      channel ring markers (`HG_SEQ_D_CANCEL` for active requests;
      `HG_SEQ_D_CANCEL_PENDING` for requests cancelled before adoption, fixing
      unadopted state-2 leaks). Detect bank slot clear (`HG_SLOT_BANK2 == 0`)
      or bank replacement (`HG_SLOT_BANK2` / `HG_SLOT_AUXC` change), issuing
      `HG_SEQ_D_LOST` and key-offs.
   3. **Pending key-off retry:** Retry any key-off previously rejected by a
      full EE staging ring.
   4. **Command adoption:** Adopt state-1 commands whose `arrival_tick <= t` in
      ascending `HG_CMD_SEQ` order, validating HSQ1 headers/tables/bounds.
   5. **Note duration expiry:** Expire active notes whose `end_tick <= t` in
      ascending `(request, track, voice)` order.
   6. **Due HSQ1 events:** Consume all track events with `due_tick == t` in
      deterministic order `(due_tick, request, track, event_index)`, respecting
      `events_per_update` budget and staging through M22 only
      (`hg_audio_ee_stage_play_voice` / `hg_audio_ee_stage_key` /
      `hg_audio_ee_stage_gain` / `hg_audio_ee_stage_pitch`).
   7. **Request & channel retirement:** Retire finished/cancelled/lost commands
      only once all owned and releasing voices for that request have retired,
      clearing `HG_CMD_STATE = 0`, `HG_CMD_SLOT = -1`, and channel `+0 = -1`.

### 4. Voice allocation, contention, repeat, and deferred-release policies

- **Allocation (`alloc_policy`):**
  - `HG_SEQ_ALLOC_LOWEST_FREE`: lowest free voice in `[voice_first, voice_first + voice_count)`.
  - `HG_SEQ_ALLOC_ROTATING_CURSOR`: rotating pool cursor wrapping cleanly across
    the configured pool without reusing releasing or owned voices.
- **Exhaustion (`contention_policy`):**
  - `HG_SEQ_CONTEND_STEAL_PRIORITY`: steal lowest-priority owned voice (ties:
    oldest `start_tick`, lowest `request`, lowest `voice`) if its priority does
    not exceed requester's; otherwise drop (`HG_SEQ_D_DROP`). Releasing voices
    remain exclusively owned until retirement and are never prematurely reused.
  - `HG_SEQ_CONTEND_REFUSE`: never steal; drop (`HG_SEQ_D_DROP`) when no free
    voice exists.
- **Repeated notes (`repeat_policy`):**
  - `HG_SEQ_REPEAT_POLYPHONIC`: allocate an independent voice per note-on.
  - `HG_SEQ_REPEAT_RETRIGGER`: release any active voice matching
    `(request, track, note)` before claiming a fresh voice
    (`HG_SEQ_R_RETRIGGER`).
- **Deferred release (`release_hold_ticks`):** When `> 0`, key-off transitions
  the voice to `RELEASING` until `due_tick + release_hold_ticks`, enforcing
  exclusive ownership and preventing premature reuse or premature request/channel
  retirement.

### 5. Documented simplifications

- Integer logical ticks rather than retail soft-double accumulators.
- Original HSQ1 fixed-length opcodes rather than retail SMF-like running status
  and VLQ deltas.
- Deterministic `release_hold_ticks` hold window rather than SPU2 hardware ADSR
  `ENVX < 2` decay polling.
- Host M22 IOP model (immediate key-off in PCM rendering; no hardware release
  envelope tail).

**Why PCM digests and non-zero frame counts differ across schedules:**
Across `unit-tick`, `coarse-2`, and `irregular-zero`, the logical decision
stream (`due_tick`, action, owner, voice, note, reason, and `logical_hash`),
ring record count, SPU2 register write count, and final resource state are
**100% identical**. However, `hg_audio_ee_flush` and `hg_audio_iop_render`
occur only at each schedule's service boundaries. When a short note's `KEY_ON`
and `KEY_OFF` both fall inside one coarse or irregular batch window, both are
staged and flushed before the post-flush `hg_audio_iop_render` call, so the
M22 host IOP (which has immediate key-off) renders fewer sounding frames for
that batched window. Repeated identical schedules are bit-exact in both
`logical_hash` and `pcm_fnv1a64`.

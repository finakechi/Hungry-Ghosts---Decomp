  stored, then replaced by −2.0 if below it (`c.lt.s`, delay-slot stores);
  `+34 += +430` (stored in the `jal` delay slot); `+430 = 0` when `0015e420`
  returns nonzero.
- **`0015e420` → `hg_player_floor`, floor hits.** `+483 &= ~2`; halfword `3f9ff2 = 0`;
  `b80` = position quad (lq/sq, w included) with `y − 2.0`; then `00145630(f12 =

### Instruction-model correction found by this evidence

The first oblique heading exposed a pre-existing defect in the shared FP oracle
(`tools/ee_subset.py`) and its C mirror. EE `mul.s` returned +0 for every zero
product, but PCSX2 keeps the IEEE sign: `0012c640` (camera up vector, modeled)
computes `sin(+0) × sin(h)` and `sin(+0) × cos(h)` with h = −2.368, and the
original stores `0x80000000` in both lanes (camera `+0x20`/`+0x28`, scratch
`70000700`/`70000708`). In M9–M11 h was −0 with cos 1, so the products were +0
and the defect stayed hidden. Zero and flushed `mul.s` products now keep
sign(fs) XOR sign(ft) in both the model and `fp_mul_bits`, with a synthetic test.
Add/sub zero results and VU products are unchanged (no evidence either way).
All M8–M11 retail regressions pass with the correction.

### Calculated versus inherited state

Each frame starts from an independently captured original dispatcher-entry state;
the calculated 1,344-byte player and 336-byte camera structures from the previous
frame are carried forward, and all 11 handoffs match the next entry capture
exactly. Within a frame, the walk/turn, constraint push, gravity, floor snap,
ground flags, history and camera are calculated. Input polling, the scene and
floor geometry, other actors and timers between frames come from the next entry
capture. This verifies the selected connected operation, not autonomous
inter-frame execution.

## Limits

Hybrid C with original-instruction-modeled floor/scene queries. One floor
material (type 2, `+47e = 0`, material 0), one wall feature, head-tier contact,
`+4ad = 0`, PCSX2 v2.8.2 FP defaults. The `+4ad` gravity, −2.0 clamp and state
restore are covered by the original-instruction differential, not retail
observation. Non-`0x100` hits and material-1 `+483` are synthetic only. No-floor,
hazard, special-surface, type-5 and spawn paths fail closed. The whole-quad snap
cannot be distinguished from a Y-only snap here (the floor probe is vertical, so
the hit's X/Z/W equal the probe's); that mutant is documented, not counted. The
floor return is checked against native `v0` only in the 12 retail frames (value 1);
the differential compares memory, not return values. Comparisons exclude the guest
stack and accept untouched libpad DMA bytes. Register readings are OCR majorities
(5 `f12` values read by eye). This is not general collision, autonomous
inter-frame execution, all-C, byte matching, a native port or whole-game
equivalence.

## Original-byte findings

### The 0013ce80 gate

```
lbu  a1, 0x3fa1b0       ; state byte 0
beq  a1, 2  -> return   ; (2, x, x) silent
beq  a1, 1  -> state-1 path
beq  a1, 0  -> state-0 path
else -> return          ; (3+, x, x) silent
```

- State-1 path: requires `0x3fa1b1 == 0`; then `0x3fa1b2 == 0` dispatches
  `00a8b800` with `f12 = 0x415f78d5, f13 = 0x461c4000, f14 = 0xc61c4000,
  f15 = f13, f16 = 0x40400000` (the observed path), and `0x3fa1b2 == 1`
  dispatches `00a8b800` with `f12 = 0x412f78d5, f13 = 0x433e0000, f14 = 0,
  f15 = 0x43530000, f16 = 0x41000000` (unobserved). Other values return.
- State-0 path: requires `0x3fa1b1 == 5` and `0x3fa1b2 == 0`, then dispatches
  the interior entry `00a8bab0` with `f12 = 0x41e80000, f13 = 0`
  (unobserved). Other values return.
- The coordinator delay-slot argument `a0 = 0x003f97f0` is unused by the
  body; the observed area body reads no argument registers.

### The 00a8b800 area body (observed corridor path)

- Opens a packet on the render stream `[gp+3098]+0x550`
  (`00155350(65535.0)`, `0014a0a0(5,2,2,0)`).
- Builds a 0x40-byte matrix in `70000780..7bf`: rows from `003eb2b0`, row 3
  clamped from `f22/f23/f24` against `[003f9300]/[003f9308]`, mirrored into
  `70000b90..bcf`; both copied to `00963a40/00963a90`.
- Emits further packet records (`00150b30`, `0014a0a0(5,0,0,0)`,
  `00153180`, `00149e50(1,1)`, `0014a0a0(1,2,0,0)`), then a sprite record
  set on stream `+0x540` (tag `0x6c020012`, matrix from `[ctx+3b0]`),
  grid data through `001537f0(10, 8)` (the `div1` site) and
  `00154100(10, 8, …)` into the `0053cd50..` region, and `00154e30` /
  `00154df0`/`0014a0a0`/`00149e50` records.
- RNG: `0011ad58` once, plus two more draws when
  `[gp+2f80] % (draw % 180 + 40) == 0` (frame 10178: three draws).

### The main-loop frame tick (narrow dependency)

`[gp+2f80]` (`0x3eaef0`) is incremented by exactly one between dispatch and
the next coordinator-entry on every observed frame (`0x3fb6` at 10164's
entry … `0x3fcb` at 10185's; constant within each frame). The increment is
the authenticated `lw v1, 0x2f80(gp) / addiu v1, v1, 1 / sw v1, 0x2f80(gp)`
sequence of the main-loop state dispatchers `00121bf4..00121c04` and
`0012d208..0012d218` — code outside the three tail services (the
MODEL+TAIL+LATE oracle writes no byte of the cell). The reconstructed
pipeline therefore performs the tick at the end of
`hg_player_frame_continuous` (after `frame_prepare_packets`, its authentic
inter-frame position), and the cell is added to the guarded RAM domains.
Without the tick the carried value is stale; the counterfactual is decisive:
running the `0013ce80` oracle on frame 10178's native camera-return capture
gives 3 draws with the native `0x3fc4`, and 1 draw with the stale `0x3fb6`.

## Reconstruction

All new code is in `src/resource_loader.c` and declared in
`src/resource_loader.h`.

- **`hg_late_frame_service` (`0013ce80`).** Emits `HG_SERVICE_MARK`
  (`0x13ce80`, 1/0) around the body, reads the three state bytes and:
  - state (1,0,0): the observed dispatch — `HG_CALL_EXTRA_FP` supplies
    `f16 = 0x40400000` (host-only seam `0xfffffff9`, consumed only by
    `0xa8b800`), then the bus call `0xa8b800` carries `f12..f15` in `a0..a3`
    (FP_SEAMS order). The area body and its callees execute original
    instructions through the connected-runtime driver.
  - state (1,0,1): domain fault `0x79` (unobserved calling state);
  - state (0,5,0): domain fault `0x7a` (unobserved sprite state);
  - every other state: silent return, exactly as the original.
- **Interpreter subset.** MMI `div1` and `mflo1` (above). The whole observed
  tree otherwise runs on the existing subset; every executed address is
  identity-checked against the authenticated ELF PT_LOAD or the
  authenticated AREA1 file.
- **Main-loop frame tick.** `[gp+2f80] += 1` at the end of
  `hg_player_frame_continuous` (see above); the cell is a guarded RAM domain
  and two compiled defect controls (missing tick, double tick) must be
  rejected.
- **Connected RNG.** The `ContinuousDriver` counts `0011ad58` executions
  inside every interpreted tree (`rng_draws`). The frame-level
  `rng-continuity` stage requires the connected path's draws to equal the
  native LCG distance from camera return to the next coordinator entry
  exactly. The M15 `rng_external` replay is deleted.

### Control observability findings (fresh measurements)

Three planned M16 corridor controls were redesigned after measured
unobservability; each replacement is detected by its intended comparator:

- **The five FP operands `f12..f16` do not affect the observed AREA body
  output.** Running `0xa8b800` on the frame-10164 camera-return capture with
  any one of `f12..f16` mutated (exponent bit flipped) leaves all 21,163
  writes, the write set, the step count and the RNG draws unchanged
  (`local/m16/experiment_fp.py`). The operands parameterize unobserved
  variants. The wrong-FP control was therefore replaced by
  `late-frame-unconditional-scratch-store`, a spurious service-owned store
  to `0x70000d00` (light-matrix region `0xc88–0xd1b`, proven not written by
  the executed tree) inside the mark bracket; the same-input comparator
  reports it as an extra write and a scratch difference at the `late-frame`
  stage.
- **Ceiling division is unobservable on the corridor.** Every observed frame
  divides `0x280` by 10 exactly (`0x280 % 10 == 0`; `trace_div1_operands.py`),
  where ceiling equals truncation. The interpreter defect control now uses a
  quotient-plus-one semantics (`div1-quotient-plus-one`) and is rejected by
  the `late-frame` differential in the grid output region.
- **Omitted area dispatch is detected by the extra-FP contract.** Omitting
  the `0xa8b800` call (and its RNG draws) cannot reach a memory comparison:
  the dispatch contract correctly reports the unconsumed `HG_CALL_EXTRA_FP`
  seam. The verifier raises a typed `ExtraFpContractFault` carrying the
  pending seam and declared consumptions, and `measure_compiled` accepts it
  as `rejected` only for the exact expected signature (pending `None`,
  declared `[]`), mirroring the `ServiceOrderFault` handling of
  `late-frame-wrong-order`.
- **Interpreter defect-control seam fixed.** The first corridor run exposed a
  real defect in the control seam itself: assigning the patch function to the
  driver's class attribute made `self.div1_semantics` a bound method, so the
  machine called it with three arguments and the control crashed instead of
  diverging. The driver now unwraps the bound method (`__func__`) before
  injecting it into the machine.

## Limits

- Observed obs3 corridor only: gate state (1,0,0); states (1,0,1) and
  (0,5,0) fail closed (0x79/0x7a); all other states return silently as the
  original does. The AREA body's other entry states (its own dispatch on
  `f12..f16`) are not explored beyond the observed execution.
- The five FP operands `f12..f16` do not affect the observed AREA body output
  (measured); wrong-FP corridor defects are therefore unobservable and the
  corresponding control was replaced (see Reconstruction).
- `div1` by zero and `INT_MIN / -1` are unobserved and fail closed.
- Packet bytes in the render streams are compared same-input only, because
  their cursor positions depend on the external services that run before
  them.
- The light-matrix bytes `0xc88–0xd1b` remain excluded at native stops: the
  rewriter runs after `00182480` and is proven not to be `0013ce80`.
- GS timing, DMA submission and the remaining tail services stay external.
- No byte matching, full-game equivalence, static recompilation or native
  port is claimed.

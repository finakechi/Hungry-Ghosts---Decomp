# M23 — cold gameplay initialization and world-state continuity

M23 investigates the gap between M21's cold boot-to-AREA1 coordinator stop
(`0012f850`) and M17's controller-driven gameplay corridor (`obs3-000`, 22
verified frames). It delivers an authenticated initialization dependency map, a
reusable C state-provenance harness (`src/scene/world_init.{h,c}`), an
independently authored original synthetic scene and connected multi-cycle
lifecycle, targeted negative controls, and a separate authentic boundary
inspector (`tools/verify_world_init.py`).

**Capability boundary:** The connected lifecycle proven here is an **original
synthetic model** exercising existing project C interfaces on the shared 32 MiB
EE RAM + 16 KiB scratchpad guest bus. It is explicitly **not** a claim of retail
gameplay equivalence from cold boot. Authentic retail execution still stops at
the first AREA1 coordinator entry (`0012f850`) before the unimplemented retail
`0012e700` sub-0 world-setup callees and `00158560` state-0 initialization
branch.

## Reusable provenance harness and original synthetic lifecycle

### Architecture and interfaces

M23 adds zero modifications to existing shared C sources (`src/game_lifecycle.c`,
`src/resource_loader.c`, `src/front_end.c`, `src/disc_read.c`, `src/scene/title_scene.c`)
and leaves all audio files (`src/audio/`, `tools/hg_audio/`) untouched.

- **`src/scene/world_init.h` & `src/scene/world_init.c`:**
  - Owns `HGWorldInitHarness`, allocating one shared `HGResourceEnv` (32 MiB EE
    RAM + 16 KiB scratchpad + `HGReadState`/`HGReadEnv` disc/pack loader).
  - Tags every tracked call and memory write with `HGValueProvenance`:
    `HG_PROV_FIXTURE`, `HG_PROV_C_PRODUCED`, `HG_PROV_SYNTHETIC_MODEL`, or
    `HG_PROV_UNKNOWN`.
  - Enforces fail-closed prerequisite validation (`hg_world_harness_validate_prereqs`)
    returning structured `HGWorldInitError` codes without crashing or guessing
    missing state.
  - Lifecycle API: `hg_world_harness_cold_boot` ->
    `hg_world_harness_publish_resources` -> `hg_world_harness_enter_world` ->
    `hg_world_harness_step_frame` -> `hg_world_harness_teardown`.
- **`tests/world_init_harness.c`:** Standalone C driver that executes two full
  cycles, verifies Cycle 1 vs Cycle 2 bit-exact trajectory parity, runs all 10
  negative controls, and emits structured JSON.
- **`tools/verify_world_init.py`:** Reusable verifier with strictly separated
  modes:
  - `--synthetic`: compiles and runs the C provenance harness under GCC/Clang
    (with optional ASan+UBSan+LSan) and validates all synthetic lifecycle
    invariants and negative controls (`evidence/m23/synthetic-lifecycle.json`).
  - `--inspect-authentic`: read-only inspection of `SCPS_150.46` and authentic
    captures (`area1-request`, `area1-active`, `obs3-000`), confirming the
    `0030f3c0` spawn table, `003db540` jump table, and live `00158560`
    `HG_DOMAIN_FAULT(0x30)` boundary on `area1-active`
    (`evidence/m23/authentic-boundary.json`).
- **`tests/test_world_init.py`:** 5 `unittest` checks covering synthetic GCC and
  Clang parity, all 10 negative controls, and authentic boundary inspection
  (gracefully skipping the authentic test only if `SCPS_150.46` / captures are
  absent).

## Original-instruction facts

These were re-read from the ELF with an extended private R5900 decoder.

- **Packet store widths.** Each 0x40-byte quad packet stores `sq $zero,0x10(base)`
  (16 bytes), then `sw +1c`, then four 64-bit `sd` stores at `+20`, `+28`,
  `+30` and `+38`. The three sites are `001991c0..d4`, `001992a0..b4` and
  `001993d0..e4`. A packet header stores only bytes 0–1 (`sh`), 3 (`sb`) and
  4–7 (`sw`). Header byte 2 and bytes 8–15 are never written, and no quad store
  reaches `+40`. The first draft used 128-bit stores and omitted the `sq` zero.
  On poisoned buffers this differs by 25 packets × 13 bytes = **325 bytes**.
- **`0014f060` register contract.** Beyond `a0..a3`, the call reads non-ABI
  `t0 = 70000ba0` (`00199278`), `t2 = record + 0x18` (`0019927c`) and
  `t1 = ctx + 0x5b0`. The `t1` context is reloaded after the packet stores
  (`001992b8`, delay slot `001992c0`).
- **`00152e90` arguments.** `a2` is the final 0x30 packet's own address (the
  cursor before its increment, `001993ec`), and `a3` is the context (`001993e8`).
  `00152e90` overwrites both before reading them.
- **The returned `v1` high lane is dead.** Every later 64-bit store overwrites
  the lane that the draft "carried", so the `0xfffffff4` seam had no effect.
  It has been removed.
- **Caller stack pointer.** The original window run from each post-counter
  stop with `sp = 0x01fffc70` reproduces the native dispatch-entry capture over
  all 32 MiB of RAM (stack included) and the full scratchpad, with 0 differing
  bytes (frames 10164–10167 measured). The earlier assumed `sp = 0x01ff8000`
  left 113 stack differences. Native window stack writes lie in
  `0x01fffb40..0x01fffc62`. The value is inferred from that exact match; it is
  not a captured register.
- **Packet streams.** The window advances four context cursors
  (`ctx + 0x544/548/54c/550`). The start-of-render routine `00148970` reloads
  cursors from the selected bank and writes packet prefixes. The verifier checks
  exact cursor starts at the next coordinator checkpoint and compares the
  resulting streams byte for byte relative to each start.
- **`0017f2d0` carried state.** `gp+0x30c0` (`003eb030..3f`) is a 16-byte copy
  of `003f9890`. `gp+0x30d0` (`003eb040`) is a smoothed accumulator
  (`0x1815a0..b4`).

## Reconstruction boundary

`hg_pre_dispatch_service` (`src/resource_loader.c`) handles the twelve observed
records and their negative sentinel, signed phase step and wrap, scratch setup
(`0x70000b80..bbf`), the exact packet store widths and the ordered callee
calls. Other record shapes fail closed (domain fault `0x61`/`0x62`). The C
delegates `00155350`, `00153020`, `00152c50`, `0014a0a0`, `0014f060` and
`00152e90` to the original-instruction interpreter. The `0014f060` registers
`t0`/`t1`/`t2` are passed by the C through the one-shot host seam
`HG_CALL_T_REGS` (`0xfffffff5`). The driver applies them only to the very next
modeled call and fails if that call is not `0014f060`. No Python-only register
initialization remains. A bridged call does not establish byte matching.

`0017f6d0`, `0017f2d0`, the render setup `00148970` and their reached callees
run through the interpreter. The later coordinator services from `0013b6e0`
onward retain their external M13 seams. The dispatcher supports the observed
active state and M12 floor branch.

The M13 counter-guard correction is unchanged: `0x2f78($gp)` is `003eaee8`
for `gp = 003e7f70`, and both guard states continue to the `00137a40`
threshold.

## First continuous failure and repair

The preserved `continuous-003.json` and the fresh
`local/m14/recovery-baseline-2.json` agree. Frame 10164 passes. At 10165 the
first divergent window store is `00155368` in `00155350`. The original starts
the queue at `0x00539470` with count 0. The old carried path starts at
`0x00539478` with count 1. Stores `00155368`/`00155374` put the eight-byte
record at the next slot, and `00155384`/`00155394` advance the stale pointer and
count again. With the original window replayed on the same old carried input,
the writes land at the same wrong slot.

`00152e90` branches at `00152f10` on `ctx+0x598` and loads the active bank's
packet data from `ctx+0x50` or `ctx+0xd0`. The old path held bank 0 at 10165,
when the original was in bank 1. The receipt reports four relative byte
differences in stream `+0x550` at `0x210/0x254/0x1800/0x1844`. The stores are
`00152f90` and `00152fd8`. Scratch and the accumulator at `003eb030..43`
already match.

The frame composition now samples the host's GS field, writes the field word
as `00149940` does, flips the bank as `00149870..80` does, then calls the original
`00148970` on the same bus. The original render loop reaches field sampling and
bank flip via `0011d9e0 -> 001496e0`, and starts the next iteration with
`0011d93c -> 00148970`. The setup resets the queue via
`0014906c -> 00155330`. The host timing model alternates the one-bit field from
the initial captured value. All packet data and queue writes are calculated
from carried state. The two-frame replay verifies that queue slot, bank,
packet bytes and the original window write set agree at 10165.

## Verification design

| Check | What it compares | Discriminates |
|---|---|---|
| `tests/test_predispatch_differential.py` (synthetic, CI) | Original `00198f60` words from the tracked packet vs the C, on 0xA5-poisoned packet and scratch buffers, with register-clobbering stubs (two profiles). Ordered call contracts. | Store widths, unwritten bytes, branch, arithmetic and contract defects. Seven compiled mutants, including the exact pre-fix widths (325 bytes). |
| `tools/verify_predispatch_window.py` (retail) | C window vs the native dispatch-entry capture, plus the window write-set check against the original-instruction oracle. | The memory domain alone cannot see the store-width defect (stale buffers); the write-set check rejects it. |
| `tools/verify_predispatch_contracts.py` (retail) | Each direct callee re-executed under the original registers, under declared-only registers with poisoned others, and under the exact bridge state. Necessity probes. Poisoned C-vs-original window differential. | Unmodeled live registers; packet bytes. |
| `tools/verify_player_continuous.py` (retail) | M13 stage domains, the twelve phases, exact render handoff fields, and the strict `pre-dispatch-window` on every frame. | Carried queue pointer/count, bank, field, cursor starts, scratch and packet outputs. |

The continuous verifier checks that the original window matches the native
dispatch capture over full RAM and scratch. For a window failure it replays
the original instructions on the reconstructed entry state. A same-input
failure identifies a window reconstruction difference. Same-input agreement
identifies a carried-input difference, whose upstream cause still needs
evidence. Both keep the strict capture comparison failed. The report gives
actual and expected bytes, absolute addresses, packet offsets and the last
original store PC for sampled differences. The omitted-bank compiled control
targets the first handoff. The restored-frame null control uses the same target.

The window write-set comparison (`predispatch_differential.compare_window`)
requires the reconstruction's write set to equal the original-instruction
write set for the same native window. It covers absolute addresses, scratch,
and the four streams relative to their cursors. Every such byte must carry the
native dispatch-entry value, and the cursor deltas must match. Every byte the
native window changes must lie in the oracle's write set. The only exclusions
are the guest stack and the libpad DMA buffers. This replaces the earlier
continuous guard of 48 phase bytes plus scratch `0xb80..0xbaf`. Window outputs
such as `003eb030..43`, the `0x700`/`0x900`/`0x940` scratch bytes, `0x9e7140…`
and the packet streams are now compared instead of excluded.

**Stack classification.** In the native window, the stack below
`0x01fffc70` (callee temporaries) is excluded, and its difference count is
recorded (112 per frame in the smoke run). Bytes `0x01fffc70..0x01ffffff`
are compared. In the continuous report, stack differences are split into
`guest-stack` and `guest-stack-caller-frames`. Both stay external, because the
host-C coordinator does not materialize its own frame. That split is reported,
not resolved.

**Unobservable by design.** On the captured state, a skipped `0012f8b8` delay
slot (`a0 = 0x60`) selects the same `0017f6d0` jump-table entry, because both
`+0x10d` bytes are 0. The pre-fix `00152e90` arguments are dead. Both are
recorded as diagnostic controls. The synthetic tests lock the call-site
arguments instead.

## Limits

The result covers the observed corridor profile and its alternating GS field.
GS timing, DMA submission and the remaining post-camera services are external.
The oracle uses verified `gp` and caller arguments, an inferred `sp` from exact
memory agreement, and zero for other entry registers. The captures read RAM
and scratch sequentially. The private decoder prints `sq`/`sd`/`lq`/`ld`, COP1
and MMI words as `???` in the packet text. The ELF bytes are authoritative.

Two native diagnostics are unobservable on the captured state and remain so
classified. One is the `0012f8b8` delay-slot skip. The other is the pre-fix
`00152e90` arguments. They are not counted as detected controls.

The M14 retail verifiers are not registered in the `hg_verify` inventory. The
79-gate regression covers the M1–M12 historical checks on the M14 source. The
690-word render-handoff packet is regenerated into ignored `local/` and is not
tracked.

Functional reconstruction and original-instruction differentials do not
establish byte-matching decompilation, full-game equivalence, a native port or
static recompilation.

# M19 — autonomous resource loading and connected area transitions

> The subsequent local integration, independent review and current
> verification are recorded in [M19–M20 review](M19-M20-review.md).

M19 connects the reconstructed lifecycle to the normal resource worker and
original Japanese media. The selected sequence reaches active AREA1 from the
title, returns to the title, and reaches active AREA1 again. The three observed
overlay writes are title → AREA1 → title → AREA1. A transition between two
distinct gameplay areas still needs its own original-game observation.

## Implementation

- `src/resource_loader.c` adds a resumable normal worker through original kinds
  0–8. It shares selector and preparation logic with the synchronous entry
  points. PACK and AREA steps, geometry, fixup and disc polling reuse M1–M7.
  The new C entry bodies are `0012ff20`, `0012ffa0` and `00131da0`.
- `HGResourceJob` is caller-owned host state. Zero-initialize it at normal
  thread start and call `hg_resource_job_resume` once on start and once on each
  normal vblank wake until it returns 1. The existing `HGResourceEnv`,
  `HGReadEnv` and original descriptor layouts are unchanged.
- `tools/resource_execution.py` supplies the normal host thread and
  asynchronous CDVD transport. Optical data comes from a single authenticated
  read-only ISO stream. Requests reject a second live normal descriptor as the
  original code does. The host uses a rising thread ID and validates wake ID,
  descriptor fields, exit order, and pending transfer state.
- `tools/run_resource_lifecycle.py` brings those seams to the M18 front-end
  runner. The M18 E3 per-frame copies of loader cells are absent on this path.
  After a single initial capture, the calculation carries task, busy, disc
  context, resource bytes, handle and arena state forward. E4 thread IDs after
  the start are generated from the initial allocator seed. `00141b10` runs as
  authenticated original instructions and clears the retained selector on
  gameplay entry and teardown. The original M18 regression runner is still
  available.
- More about request kinds, sleep boundaries and publication order is in
  [the resource-loading analysis](../analysis/resource_loading/README.md).

M18 time remains an external input for vblank, and CDVD uses a deterministic
host latency of `1 + sectors // 48` vblank ticks. The host and PCSX2 can issue
different physical chunks for the same read. There were 15,591 of 16,273
matching frame-indexed lifecycle states and 697 matching raw loader records.
Comparisons by ordered operation and completed checkpoints account for this
timing difference. The connected report records the first differences as
diagnostics.

The M18 initial state is a post-title-load capture. The cold boot to title and
the native-driven journey are separate runs. External M18 pad/DMA, analog
conversion, selected scene fades, presentation timer, name-entry decision,
render handshake, and other actor/script inputs remain. The existing priority
worker, audio/CD arbitration, PS2 kernel, IOP timing, texture upload and
render/audio output remain external. Audio registration uses the existing
M7 resource-facing model for one bank and the existing Audio harness for the
cold logo's two-bank container. No new Audio engine code is involved. The
active-mode coordinator in this run is an external call. The M13–M16 corridor
checks the existing reconstructed coordinator separately. No original
Continue, memory-card save, or new emulator replay was performed.

## Integration with M20

Use the existing raw and adjusted request entry points on the shared guest
bus. Let the loader own task phases, busy, ready transitions, and publication
through `HGResourceJob`. The original lifecycle and guest context selectors
remain the input interface. An event that depends on a loaded resource must
observe completion and the published handles. Script execution can consume
these guest fields without changing the resource or script ABI. The next
integration action is an independent review of this local branch and its
receipts alongside M20.

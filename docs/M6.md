# M6 — live PACKc6 resource processing

The selected original startup operation now calculates its resource contents through
real reconstructed processing. All **13 marked members / 1,184,000 bytes** match
independent original-game debugger outputs. The entire **1,228,800-byte** bulk read
matches at the selected loader return, including unmarked members and read padding.
The existing worker composition resolves geometry/material processing in C.
No selected transformation uses captured output, a geometry mock or an upload mock.

These are bounded original-game results in PCSX2, not PS2 silicon measurements,
whole-game equivalence, byte-matched compilation or finished rendering support.
Private recovery and GitHub delivery receipts belong in the milestone PR; they
are deliberately kept outside the immutable source/backup state they describe.

`src/resource_loader.c/.h` retain HGResourceEnv and the same memory bus. The existing
worker adapter now resolves `1386e0`. Isolated M4 fixup tests intentionally retain
the old geometry seam. Geometry selects maximum absolute X/Z bounds, performs
separately chopped squares/addition/root, scans material packet tags, clears the
original descriptor control bits and rebases both encoded address fields. Word
wrap/sign extension precedes the 64-bit ORs; values are not silently remasked to
14 bits. Types 3/4 account for their bone/vertex strides. FLK5 dispatch, linked
texture preparation, address permutation, handle publication and cache preparation
continue through the established M1–M5 code.

The strict EE interpreter adds only the investigated shifts, pcpyld, COP1 and
functional macro-VU operations. Its exact rational comparison/search oracle is
independent of the C significand/root algorithm. Undefined return registers,
exceptional FP flags, non-finite arithmetic, VU latency and arbitrary aliases into
omitted register-save slots are outside the claim. Default finite-normal behavior
needed by every selected resource is independently checked; no rendering/upload
subsystem or new loader/memory architecture was introduced.

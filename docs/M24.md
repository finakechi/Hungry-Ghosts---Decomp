# M24 · Audio sequencing and physical voice management

M24 closes the gap that M21–M22 left between `hg_audio_play` and SG2IOP
output. Before M24, a play command produced no packets until a caller passed
in resolved notes and physical voices. M24 adds two things:

1. **A read-only reference dependency map.** It covers the retail EE sound
   service from the sound request to the SG2IOP RPC. Each claim is labelled as
   observed from authenticated instruction words, inferred, or unknown.
2. **An original synthetic sequence processor and physical voice manager**
   (`src/audio/audio_sequencer.{c,h}`). Connected to the existing M22 service,
   it makes every timing, note and voice decision itself.

The model is not a reconstruction of the retail sequencer or allocator. Its
results show that the synthetic model works. They do not show retail
behaviour, retail automatic sequencing or PCM equivalence.

## A. Reference dependency map

Reproduce the scan with
`python3 -B tools/hg_audio/m24_reference_map.py ELF --check evidence/m24/reference-map.json`.
The tool refuses any other ELF. The committed map contains only addresses,
call sites and table words; it holds no instruction listings or game data.

### Ordered dependencies (confirmed from instruction words)

1. **Boot wiring** (caller around `00156878..00156954`):
   - `002a7508` sets all 16 scheduler slots at `00a6c340` (8 bytes each:
     function, counter) to the idle stub `002a72b8`.
   - `002ad288` binds SG2IOP RPC `11223344` through `00106ee8` and registers
     `002ad138` in slot 4.
   - `002a74b8(0x3c)` stores 60 into `00a6c3c4`. `002a74d0`
     (`HG_X_GLOBAL_TICK`) returns this value.
   - `002aa5e0` clears 32 channels (stride `0x9e4`), runs `002a9050` on each,
     sets `00a80158 = 1` and registers channel consumer `002a96b8` in slot 2.
   - `002ae030` clears 32 commands (stride `0x50`), sets cursor
     `00a83040 = 1` and registers `002add90` in slot 1.
   - `002b4060` registers `002b3d70` in slot 0.
   - `002b2df8` initializes 48 voice records (stride `0xf0`, base `00a832b0`)
     and registers `002b2438` in slot 3.
   - `00156920` passes the EE audio thread entry `001566c0` to `00143360`.
2. **EE audio thread** `001566c0` loops forever:
   - `SleepThread` (`00103e80`, syscall `0x32`);
   - if `002ad118` (`sceSifCheckStatRpc` on `00a82380`) reports idle, it runs
     `002a7450`;
   - it then calls `002a8ff0` for two stream records at `003f29a0`
     (stride `0x320`), followed by `00156570`.
3. **Service scheduler** `002a7450` increments `00a6c3c0`, then calls slots
   0..15 in index order and increments each slot's counter. `002a7358` binds a
   function only to an idle slot. `002a7398` returns a slot to idle.
4. **Sound request.** `00156ad0` has 917 direct call sites. It maps the sound
   ID through `00157ed0` and reads the bank slot from `003f2740`. It calls
   `002ad478` (`hg_audio_play`), then calls `002adab0` three times for
   parameter updates. If the request's limit `param3` is non-zero,
   `002ad358` enforces it per (slot, param1, param2): when the count of
   matching active commands exceeds `param3`, it cancels the command with the
   lowest `HG_CMD_SEQ` through `002ad748` and writes `-1` to that command's
   `+0x14`.
5. **Slot 1, sequence service** `002add90` runs with interrupts disabled:
   - **Retirement.** For each command in state 2 it calls `002a9d18(channel)`.
     It writes state 0 only when that call returns 0.
   - **Timing.** For each command in state 1, the 64-bit soft-double `+0x28`
     is advanced by `+0x20` (`00115fd8`). While `+0x28 >= +0x30`
     (`00116580`), the service reads the next event.
   - **Event decoding.** The status byte uses running status, kept in
     `+0x48`. The cursor is `+0x40` (`HG_CMD_SAMPLE`). The service dispatches
     through table `003bd170[status >> 4]`: `Ax → 002ae2c0`, `Bx → 002ae370`,
     `Fx → 002ae8d8`, and every other nibble returns at `002ae2b8`.
   - **Delta.** Unless flag `+0x44` is set, it reads a 7-bit variable-length
     delta into `+0x30` (`00115898`) and clears `+0x28`.
   - **Channel output.** Handlers append channel bytes to `00a83050` (count
     `00a83150`). `00a83154` holds the last emitted status, so the status byte
     is written only when it changes. `002a95c8(channel, count, buffer)`
     forwards the bytes, followed by a global record list at `00a83160`
     (count `00a83260`).
6. **Sequence handlers:**
   - `002ae2c0` (A) forwards three data bytes.
   - `002ae8d8` handles `FF 2F`: it clears the cursor, sets state 2 and
     forwards `FF 3F <byte>`.
   - `002ae370` (B) compares controller values `07`, `0a`, `41` and `60`.

   The existing `hg_audio_cancel` path (`002ad748`) forwards `ff 41 f7` to the
   same channel ring.
7. **Slot 2, channel consumer** `002a96b8`. Its table `003bd078` holds
   (handler, length) pairs. The block at `003bd0b8` maps `8x 002aa928/3`,
   `9x 002aa960/3`, `Ax 002ab508/4`, `Bx 002ac758/3`, `Cx 002ac790/2`,
   `Dx 002ac820/2`, `Ex 002ac828/3` and `Fx 002ac8d8/0x100`. The consumer
   calls `002b0cd8`, which returns 1 when any active voice record has
   `+0x0c` equal to the channel.
8. **Note handler** `002ab508` (Ax):
   - It resolves the instrument with `002b50e0` (as found in M22).
   - It releases any earlier voice for the same owner and note through
     `002b2030`. That routine sets a release ADSR through `002b1668(v,0,8)`,
     ORs the voice into the pending masks at `00a83278`/`00a8327c`, and writes
     `+0x1c = -1`.
   - It allocates in three stages: `002ae9b8(class)`; on `-1`,
     `002afed8(class, 2, …)`; on `-1`, `002af1d0(class, 2, …)`. Then
     `002b1098` claims the voice and `002b11d0` follows.
   - In `002ae9b8`, class 0 searches 24 voices and class 2 searches 48. The
     search starts at `00a832a0` modulo the range. Class 1 takes a separate
     branch.
9. **Slot 3** `002b2438` prepares the voices. M22 found that it posts gain
   (`002b2930`), pitch (`002b2c90`) and key masks (`002b2cb8..002b2dac`)
   through `002acf60`.
10. **Slot 4** `002ad138` handles the RPC:
    - If an upload transaction is pending (queue `00a823c0`, `0x14` bytes per
      entry, index `00a823ac`), it posts that transaction through `002acf60`
      and sets reply `+0x184`.
    - It then calls `sceSifCallRpc` (`001070b8`) with function 0 in no-wait
      mode 1. It sends `00a801c0` (`count*16` bytes) and receives into
      `00a821c0` (`0x1c0` bytes).
    - It clears `00a80180` and advances the transaction once the busy flag
      is 0.

### Inferences (not verified)

- The sequence stream resembles a Standard MIDI File track: running status,
  variable-length deltas and an `FF 2F` end-of-track event. `Ax` is a
  game-specific note event carrying an instrument byte.
- `HG_X_TIME_A`/`HG_X_TIME_B` (`001165d0`/`00116320`) look like libgcc
  soft-double helpers. On that reading, `hg_audio_play` stores a per-tick
  increment derived from `480.0` (high word `0x407e0000`) and the value 60.
- `002a95c8` is a bulk form of `002a94b8`. `002a9d18` reports whether the
  channel still owns voices.
- Two kinds of evidence point to round-robin allocation from the rotating
  cursor `00a832a0`. One is the code structure. The other is M22's fresh
  observations: cursor down used voices 6–7, cursor up 8–10, confirmation
  11–17.

## B. Synthetic sequence processor and voice manager

### Format (HSQ1, original)

The format is independently defined and specified in
`src/audio/audio_sequencer.h`. It uses fixed-length opcodes with no running
status and no variable-length deltas. It has a 20-byte header, a 12-byte tone
table (sample offset, root, fine, ADSR, rate scale, volume, pan) and up to
four tracks. The opcodes are END, WAIT u16, NOTE_ON, NOTE_OFF, VOLUME, BEND,
and NOTE with a duration. The resource lives at the cue address that
`hg_audio_play` resolves into `HG_CMD_SAMPLE`.

### State ownership and update order

`HGSequencer` keeps all request, track and voice state in host memory. In
guest memory it touches only the existing play commands and channels: it
reads them, writes `HG_CMD_STATE = 0` and `HG_CMD_SLOT = -1` on retirement,
and writes channel `+0 = -1`. Each call to `hg_seq_update(seq, ticks)` runs
these steps in order:

1. Advance the clock and every active track's wait.
2. Retire requests:
   - **Cancelled** (`HG_CMD_STATE == 2`): consume the channel ring bytes since
     adoption and check for `ff 41 f7`, then key off and retire.
   - **Lost** (command recycled, bank slot cleared or bank replaced): key off
     and retire.
3. Retry any key-off the service refused earlier.
4. Adopt new state-1 commands in `HG_CMD_SEQ` order and validate HSQ1. A
   malformed request is rejected and retired.
5. Expire note durations.
6. Consume every due event, older requests first and tracks in order.

Excess ticks carry forward, so coarse updates keep absolute timing. Every
event in one update is staged in that update.

### Allocation policy (original M24, simple by design)

1. **Pool.** The caller configures the pool `[voice_first, voice_first+count)`
   within 0..47.
2. **Free allocation.** Take the lowest-numbered voice that is neither owned
   nor waiting for a key-off to be staged.
3. **Exhaustion.** Steal from the owned voice with the lowest priority
   (ties: oldest start, then lowest request, then lowest voice), but only if
   its priority does not exceed the requester's. Otherwise drop the note.
4. **Ownership.** Each voice records request, track, note, start and
   priority. A note-off releases the newest voice that matches all of
   request, track and note.
5. **Release.** A voice is released on note-off, duration expiry, track end,
   steal, cancel, lost bank or command, or reset. It becomes reusable as soon
   as its key-off is staged. The host IOP model has an immediate key-off and
   no release tail.

This policy differs on purpose from the inferred retail round-robin.

### Malformed input

The processor rejects the following before it stages anything:

- bad magic, version, track count or tone count;
- out-of-range sizes or offsets;
- a misaligned sample offset or a scale/volume/pan out of range.

The following end only the affected track, releasing its voices:

- an unknown opcode;
- a read past the declared size;
- an invalid operand;
- more than `events_per_update` events in one update (default 256).

The service also refuses some notes, for example a pitch delta beyond ±36.
Each refusal is logged as `STAGE_FAIL`, and the voice is not owned.

## D. Connected operation and verification

`tests/audio_sequencer.c` runs one guest bus per scenario through this
sequence:

1. Build an original synthetic bank (four ADPCM blocks, 12 HSQ1 cues).
2. Register it with `hg_audio_register_entry`, using SIF allocation and DMA,
   `hg_audio_ee_bank_call`, flush and DMA step.
3. Submit requests with `hg_audio_play`.
4. Run `hg_seq_update`, then `hg_audio_ee_flush`, then render 800 frames
   with `hg_audio_iop_render`.
5. Cancel, release or reset.

The record streams are kept separate:

- **Inputs:** requests and ticks.
- **Model decisions:** `HGSequencer.log`.
- **Service operations:** the EE ring records counted at each flush.
- **Model output:** ordered SPU2 writes, ENVX replies and PCM (FNV-1a 64).

An independent checker runs after every flush. For each window it checks:

- key-on and key-off decisions against the SPU2 key registers;
- start addresses against the authored tone table;
- that no voice sounds without an owner, and that every owned looping voice
  is sounding;
- ownership, using only the decision stream;
- the checker's ownership against the model's own mask.

Each scenario also checks:

- the authored timeline;
- the end state: no requests, voices, commands, channels or sound left;
- determinism, by running the scenario twice.

What the scenarios cover:

- **Timed events:** a duration note, a volume and a bend restage, a second
  note, and release at track end.
- **Overlapping channels:** two requests, each with two tracks and the same
  note numbers. Each note-off releases its own voice (8, 9, 10, 11).
- **Exhaustion** (3-voice pool): a higher-priority lead steals the oldest
  low-priority voice, 20. A lowest-priority blip is dropped. A later blip
  reuses voice 20.
- **Cancel:** consumes the `ff 41 f7` marker written by `hg_audio_cancel`.
- **Bank release:** `hg_audio_slot_clear` while a note sounds gives `LOST`
  and a key-off. The cleared slot rejects play (`-4`). Re-registration
  recovers, and staging was allocated and freed twice.
- **Reset:** reset, then IOP teardown, then a rejected update while unbound.
  Re-creation and rebind follow, and a fresh request starts at voice 8.
- **Repeated requests:** 40 sequential and 6 burst requests, more than the
  32 command and channel entries. Two steals occur.
- **Malformed input:** header and bounds rejects, an unknown opcode, a
  runaway track, an out-of-range pitch refused by the service, and an
  invalid tone.

## Model responsibilities compared with the retail system

| Responsibility | Retail (map above) | M24 synthetic model | Evidence level |
| --- | --- | --- | --- |
| Request to command | `00156ad0 → 00157ed0 → 002ad478` | Same existing `hg_audio_play`; the descriptor is external | M22 reconstruction plus documented descriptor |
| Scheduling | `SleepThread`, then 16 slots per wake | `hg_seq_update` once per caller update | Retail observed (structure); period unknown |
| Event timing | Soft-double accumulator, VLQ deltas, overshoot discarded | Integer ticks, fixed WAIT, overshoot carried | Synthetic only |
| Event format | SMF-like, running status, channel byte forwarding | HSQ1, original | Synthetic only |
| Logical channel | 32 channels, 512-byte rings, consumer slot 2 | Instance per command; ring read only for cancel | Retail observed (structure) |
| Allocation | Free search from a rotating cursor by class, two fallbacks | Lowest free in a pool, priority steal or drop | Synthetic only; retail order inferred |
| Parameters / key | Slot 3 batches gain, pitch and masks | Per-note `hg_audio_ee_stage_*` | M22 instruction comparison for packets |
| Cancel / retire | State 2, then `002a9d18`, then state 0 | Key-off, then state 0 and channel `-1` in the same update | Synthetic; retail release timing unknown |
| IOP / SPU2 | SG2IOP and LIBSD | M22 host model | M22: 201 register writes; PCM equivalence untested |
